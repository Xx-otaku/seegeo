# seegeo

在自己的 Mac 上，定期记录豆包、DeepSeek、腾讯元宝官方网页的真实回答与来源。

问题列表 → 独立 Chrome 新对话 → 回答与引用提取 → SQLite 历史 → 本机网页阅读、对照和导出。

## 启动

需要 macOS 和已安装的 Google Chrome。

1. 首次双击 `Setup.command` 安装依赖并构建。
2. 双击 `Start.command`，浏览器打开 `http://127.0.0.1:4317`。
3. 在「运行设置 → 平台与登录」打开三家的独立窗口，自己完成登录。
4. 在问题库粘贴问题或导入 UTF-8 CSV，手动开始一轮。
5. 新安装需每个平台至少完成两条采集，并核对回答、引用和来源列表，再点「两条结果已核对」启用定时监测。

已有 Node.js 24 时直接使用；否则脚本从 Node.js 官方下载并校验 SHA-256，安装到项目的 `.runtime/`，不修改系统安装。运行不依赖 Codex。首次安装需要联网；后续启动依赖本机已有文件及平台网络。每次运行 `Start.command` 会先重新构建面板，确保升级或切换 Git 版本后界面与服务匹配。

若系统没有按双击执行，可在终端运行：

```sh
cd /你的路径/seegeo
sh Setup.command
sh Start.command
```

关闭网页不会关闭服务。运行终端需要保持打开；按 Ctrl+C 或在「运行设置」退出。服务不会随 Mac 登录自动启动。

开发命令（Node.js 24）：

```sh
npm ci
npm run build
npm start
npm test
```

`npm run dev` 自动重载服务，另开终端 `npm run dev:ui` 启动 Vite 面板。可用 `SEEGEO_PORT` 更改服务端口，用 `SEEGEO_DATA_DIR` 设置独立数据目录。

## 使用与采样口径

- 每题每平台采样一次，独立新对话；每轮保存问题原文和版本。
- DeepSeek 显式开启智能搜索、关闭深度思考。
- 当前豆包、元宝采用快速模式和平台自动联网；保持问题原文，不通过追加提示强迫搜索。可以在设置中关闭允许自动联网，此时无法确认强制搜索的平台会停止提交。
- 记录可识别的模型；网页未公开模型名称时留空，不推测后端模型。平台默认模型可能变化。
- 三平台采用独立持久 Chrome 用户目录，账号登录及验证码由用户处理。
- 默认串行、任务之间间隔 3 秒，采集时用 macOS `caffeinate` 防止空闲休眠；合盖、断网或主动休眠仍会中断。

「引用与来源」分别显示正文实际引用、平台检索参考列表。搜索列表里的文章不一定被正文引用。仅保存平台展示的信息，不抓来源文章全文；豆包报告的参考资料总数可能多于展开列表里的链接数，面板分别显示两者，未展示的链接无法采集。来源统计基于实际展示并提取的链接，不代表平台报告的全部资料；豆包部分来源卡片通过打开目标标签读取 URL 后关闭。引用对应正文仅在页面能核实时保存。

回答阅读视图整理网页引用标记；数据库及 CSV/JSON 保留平台原始文本。来源链接按实际 URL 保存；签名链接、跳转链接或参数变化可能在对照中被视为不同来源。

## 问题导入

纯文本每行一题。CSV 可包含「问题」「分组」列，也支持 `question/text`、`group/group_name` 英文列名；无表头时第一列作为问题。

```csv
问题,分组
适合小团队的项目管理工具有哪些？,行业问题
"选购便携咖啡机，需要考虑哪些因素？",产品问题
```

CSV 带引号的多行内容作为同一个问题；空行和原文完全相同的问题跳过。编辑问题会递增版本，历史结果保存采集时的原文。移出问题库后，历史仍可从采集记录打开。勾选多个问题或全选当前筛选结果后，点击「删除所选」可批量移出；筛选之外的已选项会显示数量，确认后一起处理。已有批次继续使用原问题快照。左下角版本号自动读取项目配置，当前为 v0.4.2。

## 调度与恢复

默认北京时间每周一 09:00，可切换每日并修改时间。需要手动启动服务、Mac 开机联网，并完成三平台采集验证。

服务启动后检查最近一次计划时点，错过多轮也只补最近一轮；计划时间和实际采集时间分别保存。已有未完成批次时优先完成该批次，不堆积过期任务。

| 状态 | 含义与操作 |
| --- | --- |
| 已完成 | 已确认完整回答，来源已提取或未展示来源 |
| 来源待核对 | 回答已保存，但来源未完全提取；可核对原会话 |
| 需要登录 / 需要验证 | 等待人工处理约 60 秒后跳过当前项，其他任务继续；处理后可单条重采 |
| 需核对会话 | 异常中断或提交结果待核对；继续时先核对原问题和原会话 |
| 已暂停 | 手动暂停保留当前项，点击顶部「继续监测」优先恢复它 |
| 已取消 | 本轮停止，已完成答案与来源保留，可立即开始新轮或重跑 |
| 采集失败 | 本次未能取得合格结果，可检查异常证据后另开对话重采 |

四个页面和阅读详情共享顶部任务控制栏：

- **暂停/继续**：先停止当前项。采集器能及时退出时保留原页面；否则关闭该采集标签，保留登录态。继续优先核对原问题、恢复已有回答或等待生成；会话失效时另开对话重试一次，并记录尝试过程。登录或验证码需要人工处理，不会因此自动重新发送。
- **取消监测**：运行、暂停和等待人工处理时都可直接取消。停止当前采集，取消剩余项目，保留已完成结果，迟到结果不会覆盖取消状态。未来计划保留，同一计划槽不立即补跑。
- **重新运行本轮**：创建新批次，沿用原批次的全部问题版本和平台范围；即使问题后来编辑、停用或移出，重跑范围仍保持一致。采集记录页也可选择旧批次重跑。
- **另开对话重采**：为单条结果创建新批次并立即运行。已有未完成批次时，界面说明需要先完成或取消当前轮。
- **查看原会话**：使用对应平台的采集 Chrome 登录态打开，不依赖日常浏览器登录。

快速重复点击的命令串行处理，只允许一个采集 worker。服务重启后，意外中断的批次保持暂停，等待主动继续。未提交的瞬时网络错误最多有限重试；任务尝试记录可在 JSON 导出中查看。历史差异只比较两条已完成记录，避免把未生成的答案解释为内容删除。

### 一键重采未完成任务

任务控制栏的「一键重采未完成」会统计每个已启用、未移出问题在各平台的**最新**结果：采集失败、超时跳过、来源待核对和待核对会话会纳入；主动取消的任务不纳入。旧失败记录若被之后的成功结果覆盖，不会重复采集。确认框列出平台与数量，请先检查范围，再开始。

执行时创建独立批次，保留原结果、采集时的问题版本及平台。已提交且有原会话和模式记录的任务先核对原会话；无法恢复时再另开对话。正在运行或暂停的批次需先完成或取消；暂停的项目也可使用「继续监测」。没有待重采项目时按钮不可用。该操作不会自动排除某个平台，请按确认框核对平台。

## 导出、数据与备份

- 回答 CSV：问题、版本、平台、时间、模式、原始答案、来源状态及错误。
- 来源 CSV：关联任务、来源类型、标题、URL、站点、摘要和引用标号等。
- JSON（schemaVersion 2）：完整结构、批次控制状态、计划时间、实际时间、任务关联及 attemptsLog 尝试记录。

CSV 为 UTF-8 BOM，兼容 Excel；可能被表格软件执行为公式的字段加安全前缀，原始内容仍保留在 JSON。

默认数据目录：

```text
~/Library/Application Support/seegeo/
  seegeo.sqlite       问题、任务、答案、来源、设置及事件
  backups/            数据库版本迁移前自动备份
  profiles/           三家独立浏览器登录态
  diagnostics/        异常截图和诊断；保留 30 天
```

首次升级到数据库 v2 会自动在 `backups/` 中备份 SQLite，再执行事务迁移。旧版手动暂停遗留的待核对项会转为可恢复暂停，升级不会自动启动它们。升级后不应直接用旧程序打开 v2；需要回滚时先退出服务，将备份复制为 `seegeo.sqlite`，并移除旧 WAL/SHM 文件后再启动匹配版本。

文本历史长期保留。备份时先退出服务，再复制整个数据目录；恢复时退出服务后放回原目录。备份含登录态，请保存在自己的存储位置。不要把这个目录提交到 Git。

完成、异常和需要人工操作时发送 Mac 系统通知，面板也保留事件。系统通知权限或系统设置导致通知不可用时，请以面板为准。

## 验证与限制

2026-10-26，在真实账号上完成三平台各两题采集及一轮六任务的正式队列验证；验证码后恢复原会话也已验证。测试问题是公开的航天发射日期和故宫票务信息，不代表完整业务问题集已验收。

正式六任务批次耗时约 129 秒。每平台仅两条样本，不能据此保证长期吞吐或成功率。网页改版、账号配额、登录失效和验证码仍可能导致暂停；故障应保留为明确状态，不能用整页文字或旧答案充当成功。

任务控制和新版界面验收见 [验证记录](verification.md)。`npm test` 包括可控采集器替身和隔离 HTTP/Chrome 面板按钮检查；浏览器命令在按钮测试中使用明确替身，不连接真实账号。`npx tsx scripts/live-controls.ts --live` 是显式开启的真实账号回归工具，使用独立测试数据库；运行前请退出正式服务，避免同时占用采集 profile。不要把真实账号验证加入无人值守 CI。

本机工具，暂不支持多用户、服务器部署、API 替代采样、附件、多轮追问及来源文章全文采集。

技术结构见 [architecture.md](architecture.md)，验证记录见 [verification.md](verification.md)。本项目独立实现，参考 [geo-monitor](https://github.com/eric1981/geo-monitor) 理解平台适配器与历史存储流程。MIT License。

## v0.2.1：采集记录批量删除

采集记录页可勾选或全选当前列表中已结束批次的记录后删除。确认后清除对应回答、来源及尝试信息，从阅读、导出、问题最新状态和统计中移除；问题库保留，批次的问题版本和平台范围仍用于整轮重跑。进行中的批次需先完成或取消。既有备份不随删除修改。

## v0.4.0：按轮保存基线

基线分析中按北京时间选择测试日期，显示该日期发起的监测问题（已移出的问题和已删除记录不显示），问题列表默认收起，可展开逐项勾选、全选或沿用上一份已保存的较早日期选择。汇总表默认只展示每类来源比例最高的三个网站，可展开查看全部；采集时间与样本情况可单独展开。单条及批量补采归属原轮发起日期，即使跨天完成也不会分到新日期。同日同题同平台有多次结果时，使用最新有效回答，失败不覆盖此前有效结果；保留实际采集时间。整轮重跑归属其自身开始日期，若在同一天会与当日其他监测合并选择。

「投放内容链接库」支持自定义渠道、批量添加链接、编辑备用链接、批量移动与删除。按规范化文章链接匹配，去除锚点与 utm 追踪参数；不按整站匹配。正文引用与检索参考分别计数，同一回答同链接去重，跨回答分别计次；只统计来源提取完整的回答。豆包报告参考总数可能高于页面展开的链接数，统计仅包含实际展示并保存的链接。

品牌提及率、品牌声量份额和 TOP3 率仅使用问题原文不含目标品牌及别名的有效回答；只含竞品名的问题保留。声量分母仅含配置的品牌和别名，按名称出现次数计算；TOP3 分母只含明确可判定排名的回答，仅按明确排名自动识别，不再提供人工核对。来源使用整轮有效回答。无来源或无可判定样本显示无数据，不作为 0。

选择日期和问题后点击「保存本轮基线」，报告固定当时的品牌、链接、核对、样本与结果。可保存不完整轮次，表格会展示缺失情况；以后修改配置或删除采集记录不会修改旧报告。再次保存同一轮生成修订版，原版保留。历史表默认显示各轮最新修订；可显示全部修订并分别删除。两轮对比显示百分比变化和网站比例增减，配置或样本不同会提示。导出 Excel 或 JSON；报告不包含来源文章全文，本版不统计回答结构比例。

数据库 v6 升级前自动备份；回退到旧版本前需先退出服务并恢复匹配的数据库备份。已有历史轮次首次保存采用当前确认配置，不代表历史采集时的配置。已保存报告单独管理，即使删除原采集记录也会保留。旧版报告保持原有快照，其中可能含历史人工核对；新日期报告不采用历史人工核对结果。

## v0.3.1：超时恢复与跳过

「运行设置 → 异常恢复与超时跳过」可调整每项总时限（默认5分钟）、单次等待（120秒）和自动恢复次数（1次）。总时限覆盖打开浏览器、生成、原会话恢复、新对话回退和来源提取；达到时限后保留诊断，标为跳过并继续，未完成不算成功。登录/验证码等待约60秒后也会跳过当前项，可处理后单条重采。手动暂停不消耗后续恢复窗口，继续时重新计时。新批次按问题轮换三平台，避免同一平台连续50次采集。
